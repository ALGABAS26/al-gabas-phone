# إشعار جاهزية جهاز الصيانة عبر WhatsApp (مجهز وغير منشور)

الدالة جاهزة برمجيًا فقط ولم يتم نشرها. تستدعى بعد تحويل أمر صيانة مملوك للمستخدم الحالي إلى الحالة `ready`، وتتحقق من جلسة المستخدم وملكية الأمر وحالته ورقم الهاتف قبل أي اتصال بمزود الخدمة.

## مفتاح الأمان

- `WA_SEND_ENABLED` يجب أن يظل غير مضبوط أو يساوي `false` حتى نكمل إعداد Meta والاختبارات ونوافق صراحة على التشغيل.
- لا يوجد أي مفتاح أو رقم Meta داخل التطبيق أو `config.js`.
- الدالة ترفض الطلب قبل أي اتصال بواتساب ما لم تكن قيمة `WA_SEND_ENABLED` هي النص الحرفي `true`.
- لا يتم نشر الدالة أو إنشاء أسرار Meta في هذه المرحلة.

## قالب Meta المطلوب لاحقًا

`أهلاً {{1}}، جهازك {{2}} (أمر صيانة {{3}}) جاهز للاستلام من المحل.`

يلزم اعتماد قالب Utility بثلاثة متغيرات نصية بالترتيب: اسم العميل، الجهاز، رقم أمر الصيانة.

## أسرار الخادم المطلوبة بعد ضبط Meta

- `WA_SEND_ENABLED=false` عند أول نشر واختبار
- `WA_ACCESS_TOKEN`
- `WA_PHONE_NUMBER_ID`
- `WA_MAINTENANCE_READY_TEMPLATE_NAME`
- `WA_TEMPLATE_LANGUAGE=ar`
- `WA_GRAPH_API_VERSION` (الافتراضي `v25.0`)
- أسرار Supabase الافتراضية، ومنها `SUPABASE_SERVICE_ROLE_KEY` على الخادم فقط

## حماية التكرار

يجب مراجعة وتشغيل ملف SQL المقترح على قاعدة اختبار أولًا. سجل المحاولات فريد لكل أمر صيانة، ولا يعيد إرسال الحالات المقبولة أو غير المؤكدة تلقائيًا؛ يسمح بإعادة محاولة الحالة الفاشلة فقط وفق إجراء يدوي مضبوط.

لم يتم نشر الدالة، ولم يتم إرسال أي رسالة حقيقية، ولم يتم تعديل قاعدة الإنتاج.
