# إرسال فاتورة البيع كملف PDF عبر WhatsApp Cloud API

الدالة مجهزة برمجيًا وغير منشورة. لا ترسل أي رسالة ما لم يكن مفتاح الخادم `WA_SEND_ENABLED` مساويًا للنص `true`، كما أن مفتاح العميل يظل `WA_CLIENT_SEND_ENABLED=false`.

## طريقة العمل
1. التطبيق يقرأ الفاتورة وأصنافها من Supabase بجلسة المستخدم الحالية.
2. يرسم الفاتورة العربية على Canvas ثم يقسمها إلى صفحات A4.
3. يحوّل كل صفحة إلى JPEG داخل ملف PDF متعدد الصفحات؛ يحافظ ذلك على تشكيل العربية وتخطيط الفاتورة، لكن النص داخل PDF غير قابل للتحديد أو البحث.
4. يرسل التطبيق ملف PDF إلى الدالة مع JWT.
5. تتحقق الدالة من ملكية الفاتورة وحالتها ورقم العميل، وتتحقق من ترويسة PDF وحجمه.
6. تحجز محاولة واحدة للفواتير عبر RPC سجل الإرسال، ثم ترفع PDF إلى WhatsApp Cloud API وتستخدم قالبًا معتمدًا برأس DOCUMENT.

## الأسرار المطلوبة على الخادم
- `WA_SEND_ENABLED=false` أثناء التجهيز والاختبار.
- `WA_ACCESS_TOKEN`
- `WA_PHONE_NUMBER_ID`
- `WA_DOCUMENT_TEMPLATE_NAME` (قالب معتمد برأس DOCUMENT)
- `WA_TEMPLATE_LANGUAGE=ar`
- `WA_GRAPH_API_VERSION=v25.0`
- `SUPABASE_SERVICE_ROLE_KEY` على الخادم فقط.

## قاعدة البيانات
تستخدم الدالة RPC الحالي `erp_wa_claim_invoice_delivery` و`erp_wa_update_invoice_delivery`. يجب مراجعة ملف `supabase/proposals/whatsapp-meta-webhook-rpc.sql` وتطبيق نسخة claim الجديدة في قاعدة اختبار منفصلة قبل النشر؛ فهي توحّد منع التكرار بين مسار الصورة القديم ومسار PDF الجديد. لا تطبقها على الإنتاج دون اختبار ومراجعة.

## القيود
- لا يوجد نشر أو إعداد Meta في هذه المرحلة.
- لم يتم إرسال أي رسالة حقيقية.
- لا يتم توليد PDF على الخادم؛ التوليد داخل التطبيق.
- PDF صورة-داخل-ملف PDF، وليس PDF نصيًا قابلاً للبحث.
